## 二、架构稳健性评估：B+

### 强项

1. **分层清晰** — Ports/Adapters 模式落地到位，5 个 Protocol 接口（EventBus/Interaction/LLM/MCP/Repo）实现了依赖反转，服务层不依赖具体实现
2. **异步一致** — FastAPI + aiosqlite + asyncio 全链路非阻塞
3. **事件驱动** — Domain Event → EventBus → WebSocket 广播，前后端解耦
4. **状态机形式化** — Harness 状态机管理任务生命周期 + DAG 校验，Phase 12 修补了 PENDING⇄PAUSED 的缺失转换
5. **MCP 手写包装** — 吸取 v2 动态注入的教训，用 Pydantic 严格校验参数，设计合理

### 弱项

| 问题 | 严重度 | 说明 |
|------|--------|------|
| 测试覆盖不足 | **高** | 36 个测试多为冒烟测试，缺少服务集成测试、API 契约测试、错误路径测试 |
| 未实现的桩 | 中 | `log_svc.py`、`experience_repo.py` 抛 NotImplementedError，运行时若触发会崩溃 |
| 大服务文件 | 低 | `workflow_svc.py`(428行)、`inception_svc.py`(386行) 接近拆分临界点 |
| lifecycle 硬编码 | 低 | `routes_lifecycle.py` 的 `active_tasks` 硬编码为 0 |
| 前端零单元测试 | 中 | Vitest 配好了但 src/ 下无测试文件 |

## 三、计划书可行性评估：A-

plan.md（829 行）覆盖了系统愿景、核心特性、技术选型、目录结构、9 阶段路线、PRD 对齐、生命周期、风险缓解。

| 维度 | 评价 |
|------|------|
| 技术选型 | 合理。Tauri 2.x 解决包体积问题，ADR-001 论证充分 |
| 架构设计 | 可落地。Port 层 100% 实现，LLM Gateway 双 adapter 通过测试 |
| 工作量估算 | 偏乐观。原计划 9 Phase，实际扩展到 12，初始估算漏了 LLM Gateway 和 Port 层补全 |
| MVP 边界 | 清晰。排除了自动更新、多项目并发、RAG、i18n、第三方 LLM 插件 |
| 风险识别 | 到位。MCP 不稳定、LLM 幻觉、sidecar 崩溃等均有缓解策略 |

### 隐患

plan §11.6 的 MCP 手写包装要求为每个 MCP 工具写一个 BaseTool 子类。工具数量增长时维护成本线性增长。建议未来考虑半自动代码生成（MCP schema → BaseTool 模板）。
